# Data card — Chinor SFT data v1

Supervised fine-tuning data for the Chinor Bank Assistant (Stage 2). Built by `data/build_sft.py`; the files and
their SHA-256 are listed in `manifest.sha256`. Training refuses to start without that manifest
(`scripts/h200/run_matrix.sh`).

## Token lengths

`Qwen/Qwen3-0.6B-Base` tokenizer (identical across Qwen3 sizes), full rendered example: min 496, median 537, p99
590, max 626 (`task-2268`); 100 % ≤ 1,024 tokens (training `max_length`), so nothing is truncated. Most of each
example is the system prompt; the supervised part is the assistant turn(s) plus `<|im_end|>`.

## Checks (all pass; any failure stops the build)

- 0 examples from the 10 held-out intents.
- Contamination against `eval/eval_set.jsonl` (all messages of every example): train 0 exact, 0 fuzzy (ratio ≥ 90),
  word 8-gram overlap 1.01 % of eval 8-grams (shared handbook wording); val 0 / 0 / 0 %.
- Every assistant turn passes `data/verify.py` v2 (rules a–g) against its intent.
- 40 task examples per intent (min = max = 40).
- Masking on 3 real examples (`task-2616`, `sft-B3I-008`, `sft-D-009`): only assistant text + `<|im_end|>` is
  supervised; system, user and assistant headers are masked — `docs/masking_example_v1.md`.

## Why canonical answers (ADR-024)

The task turns were first going to be rewrites of the canonical answers generated by `Qwen/Qwen3-32B` (n = 2 per
prompt, `results/c1-rewrites/`), filtered by verifier v2 and, after the first audit, by an entailment judge. Two
manual audits of accepted rewrites measured how often a rewrite states something the handbook does not
(Wilson 95 % CI):

| Audit | Selection | Rows | Marked unsupported | Rate | 95 % CI |
|---|---|---|---|---|---|
| 1 (`eval/audit/rewrites_sample.csv`) | v2 (verifier v2 only) | 50 | 8 | 16.0 % | 8.3–28.5 % |
| 2 (`eval/audit/rewrites_sample_2.csv`) | v3 (verifier v2 + entailment) | 30 | 5 | 16.7 % | 7.3–33.6 % |

The target was ≤ 5 % (audit 2 rule: ≤ 1 / 30). The entailment filter did not lower the rate measurably. The
judge passed all 30 audit-2 rows, so it agreed with the author on 25 / 30, and all five audit-2 errors are
condition or scope shifts: a handbook fact attached to a condition or scope the handbook does not give.

| Id | Intent | Unsupported part | Kind |
|---|---|---|---|
| task-1300 | getting_spare_card | "an additional card costs 35,000 UZS" | condition |
| task-2109 | top_up_limits | "If a single deposit exceeds 10,000,000 UZS" | scope |
| task-0453 | card_not_working | "If the card is damaged and fails at every terminal, it will be replaced free of charge" | condition |
| task-0327 | card_acceptance | "If a transaction is declined" | scope |
| task-0982 | exchange_charge | "Any amount beyond that incurs a 0.6 % fee" | condition |

Every word and number in these sentences is in the premise, so neither the lexical rules nor a sentence-level
entailment judge catch them reliably. A bank assistant that teaches the model wrong conditions on fees and limits
is the failure the project is meant to prevent.

**Decision.** SFT v1 uses the canonical answer verbatim for every task prompt, plus the approved behaviour
examples. The rewrites, both audits and the judge records are kept; the rewrites are one ablation arm
(`data/sft/v1_rewrite/`, below).

**Cost.** The 40 queries of an intent all share one target answer, so the task data teaches no variation in
wording: the model may learn to reproduce the canonical answer for anything near the intent, and phrasing
diversity has to come from the behaviour examples. The ablation measures what the rewrites would have added.

## Ablation data: `data/sft/v1_rewrite/`

Identical to v1 (same prompts, ids, behaviour examples, seed and split) except the task assistant turns: the
selection-v3 rewrite where one passed (1,997 rewrites, 328 rewrites identical to the canonical answer), else the
canonical answer (355). The data files are git-ignored; `manifest.sha256`, `task_stats.json` and
`assemble_stats.json` are committed, and `build_sft.py --stage task --selection v3 --task-out data/sft/v1_rewrite`
then `--stage assemble --src-dir data/sft/v1_rewrite --out-dir data/sft/v1_rewrite` rebuilds them byte for byte.
Used only for the ablation run (14B SFT-LoRA seed 0); never for headline arms.

## Entailment filter (ADR-022)

Every generated rewrite that passes verifier v2 (rules a–g) is also checked sentence by sentence by an
entailment judge from a different model family than the generator (`Qwen/Qwen3-32B`) and the policy (Qwen3 base).

- **Judge:** `google/gemma-4-31B-it`, revision `842da3794eaa0b77d5f08bae87a17459d91ff475`, bf16, transformers
  5.21.0 (`Gemma4ForConditionalGeneration`), greedy, JSON output.
- **Premise / hypothesis:** premise = the intent's canonical answer + the customer message only (no system
  prompt); hypothesis = one sentence of the candidate. Labels: entailed / neutral / contradicted. Hedges ("may",
  "usually", "in most cases"), added conditions, channels, contacts, advice and promises are neutral unless the
  premise states them.
- **Pass rule:** a candidate passes only if every sentence is entailed; an unparsable judge reply counts as neutral.
- **Prompt:** version 1 (`data/entail_judge.py`, `RULES_V1`), the first attempt; no revision was needed.
- **Validation** on the 50 rewrites of the first manual audit (`eval/audit/rewrites_sample.csv`, 8 marked as
  containing an unsupported claim). Threshold rule, fixed before the run: the judge must flag ≥ 7 of the 8
  marked rows and ≤ 4 of the 42 unmarked rows. Result: **pass**.

  | | Judge flagged | Judge passed |
  |---|---|---|
  | Marked unsupported (8) | 7 | 1 |
  | Unmarked (42) | 3 | 39 |

  - Miss (marked, judge passed): task-0465 `card_not_working`, the outcome sentence "If the daily limit has been
    reached or the card is damaged, it will not work for transactions." — the judge treated it as following from
    the premise.
  - False flags (unmarked, judge flagged):
    - task-0050 `age_limit`: "She will need a passport or national ID card…" — the judge read the unknown age
      and residency as making the requirement conditional;
    - task-0367 `card_delivery_estimate`: "express delivery … 2 business days for a fee of 45,000 UZS" — the
      judge saw a conflict with "the first physical card has no delivery fee" (both hold in the handbook);
    - task-2625 `wrong_amount_of_cash_received`: "It seems there may have been an issue with your
      withdrawal." — a genuine hedge.
  - 125 sentences, 0 unparsable replies; 32 s of generation (3.9 sentences/s, batch 16).
- **Full pass** over all 5,048 v2-passing candidates (12,297 sentences), run `judge-full-v1`
  (`results/c1-rewrites/entail_verdicts.jsonl`): 4,322 candidates entailed. Selection v3 over the 2,680 prompts:
  1,997 rewrites, 328 passing candidates identical to the canonical answer, 355 canonical fallbacks. Audit 2 on
  30 fresh v3 rows: 5 / 30 unsupported (above), so the filtered rewrites are not used in v1.

## Limitations

- One target answer per intent (see Cost above); the model may over-fit to canonical wording.
- 160 behaviour examples, all written by one author; categories have 10–40 examples each.
- English only; queries are Banking77 style (short, single-turn) except the B1-dialogue examples.
- The handbook is fictional; facts about Chinor Bank are not facts about any real bank.
